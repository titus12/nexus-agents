Multi-Agent Task Orchestration

Review Orchestrator

一个围绕任务进行分析、规划和审查的多 Agent 编排机制，帮助团队把复杂问题转化为清晰、可验证、可交付的方案。

它能做什么？

理解任务需求收集和核验证据拆分 group / item制定执行方案检查风险和边界处理异常和重试输出最终交付方案

核心流程

收集证据
识别未知项
→
规划师拆分任务
制定执行方案
明确验收标准
→
审查员审查证据
检查风险
决定通过或修订
中书省：拆解需求，整理线索，形成总体方案。
门下省：针对每个 item 制定实现方案，形成具体执行方案。
最终：所有 item 和 group 完成后，汇总生成完整交付方案。

三个角色

Analyst · 分析师

负责事实核验、证据收集、需求覆盖分析，以及识别证据缺口。

Solver · 规划师

基于分析结果制定实现或调研方案，明确范围、步骤和验收方式。

Critic · 审查员

检查方案是否合理、完整、可验证，并指出 P0/P1/P2 等风险问题。

它带来的价值

  • 职责分离，降低单个 Agent 判断错误的风险。
  • 所有结论基于证据，减少无依据的方案输出。
  • 按 group 和 item 推进，复杂任务更容易跟踪。
  • 审查不通过时可回到当前任务重新规划。
  • 对超时、字段缺失和非结构化回复进行重试或修复。
  • 最终输出结构统一，方便开发人员理解和执行。
