# Workflow Token Usage Evaluation Design

Date: 2026-06-24

## Goal

Bind token usage to workflow evaluation by carrying a workflow run ID and role through Codex proxy requests, aggregating usage in Nexus, and writing the aggregate into task-run metrics before evaluation.

## Decisions

- Use HTTP headers only; no request-body metadata fallback.
- Reuse the existing workflow run ID generated by `POST /api/workflow-runs/start` as the token attribution key.
- Capture role with `X-Nexus-Workflow-Role` so multi-role workflows can identify which role spends tokens.
- Keep request events minimal: workflow run ID, role, model, input/cached/output/total tokens, timestamp.
- Store workflow-level aggregate metrics in the existing evaluation store data, not in a separate database.
- Write token aggregate into `TaskRun.Metrics["tokenUsage"]` when a workflow run completes or fails.

## Headers

```text
X-Nexus-Workflow-Run-Id: wf_run_...
X-Nexus-Workflow-Role: planner|worker|reviewer|tester|arbiter|unknown
```

If `X-Nexus-Workflow-Run-Id` is missing, the router still serves the request but does not record workflow token usage.
If role is missing, the router records role as `unknown`.

## Data model

```go
type TokenUsageEvent struct {
    WorkflowRunID     string `json:"workflowRunId"`
    Role              string `json:"role,omitempty"`
    Model             string `json:"model"`
    InputTokens       int    `json:"inputTokens"`
    CachedInputTokens int    `json:"cachedInputTokens"`
    OutputTokens      int    `json:"outputTokens"`
    TotalTokens       int    `json:"totalTokens"`
    CreatedAt         string `json:"createdAt"`
}
```

Aggregated task metric shape:

```json
{
  "tokenUsage": {

```

## Evaluation behavior

`evaluateTaskRun` reads `metrics.tokenUsage` and adds `tokenEfficiencyScore` plus token-related causes/issues. Missing token metrics should not fail or heavily penalize legacy task runs; it should be visible as missing data.

## First implementation scope

- Header-based router recording.
- Evaluation-store aggregation by workflow run ID and role.
- Workflow completion attaches aggregate token usage to task-run metrics.
- Rule evaluator emits token efficiency score and token causes.
- Backend tests cover router recording, aggregation, and evaluation scoring.

## Out of scope

- Cost in currency.
- Node-level attribution.
- Metadata/body fallback.
- Full token billing dashboard.
- Storing request prompts or response content.
