# One requirements document and human revision loop

Approved behavior: only the exact trimmed reply `通过` approves the currently offered document. Every other nonempty reply is complete input to a real Solver LLM revision. Per the user's subsequent correction, human-requested revisions pass mechanical form/version/graph/dependency checks and return directly to human review, without a Critic or freeze-check LLM round. Initial machine planning retains its Critic flow. There is no automatic approval, synonym approval, or human-round exhaustion that hands over to Menxia.

The single published artifact is `zhongshu-requirements.md`. Its versioned bytes combine task metadata, the validated task table and each authoritative group document exactly once. The immutable review snapshot records its hash, graph hash and group hashes. Feishu displays those stored bytes and Menxia receives those same stored bytes. Group-specific validation extracts its marked chapter from that artifact; no separately rewritten human summary is a handoff input.

Feedback is persisted in full with message identity, author and reviewed version. A human revision revokes prior approval, opens the planning scope, resets machine convergence counters and removes unexecuted Menxia caches. The Solver receives the complete prior document, current task graph, original requirements and complete current feedback. It returns the full revised graph and group documents, permitting added/reorganized tasks. The orchestrator validates and publishes this result directly to the human, without dispatching Critic or Analyst. Mechanically eligible group documents are frozen for handoff, but no machine-review approval is fabricated in the ledger. The next human gate has a fresh decision id and document hash; replies to older gates cannot approve it.

Only after matching document, graph and group hashes and a `通过` event does the workflow dispatch Menxia. Mechanical freeze and fast track cannot substitute for this decision. The production entrypoint always enables this gate even if a legacy/environment flag is false. Explicit notification-isolated offline gate=false fixtures retain their documented machine-only behavior. Existing live tasks and the active 8766 service are not restarted or rewound.

Validation uses `cmd/run_tests.py` and scripted Multica/Feishu ports: multiple revisions, long feedback, arbitrary approval-looking replies, exact pass, stale message ids/hash drift, persisted restart, Unicode parts, multi-group chapter isolation, task addition, renewed freeze, and byte-identical human/Menxia document delivery. Real agents/skills are read back through the existing sync utility; no live model round is needed for deterministic mechanisms.

Replies added to older review threads while the synchronous LLM was busy are recovered at the next gate. Only fresh non-approval comments can cause another revision; older pass replies never approve a newer document. Feedback keeps its original reviewed version and hash.
