# 中书省完整文档送审设计

用户于 2026-10-05 回复“实施”，批准本设计。

用户反馈：飞书将一份中书省方案拆成多条消息，不便连续阅读。

## 建议方案

每轮中书省送审发布一份完整飞书文档，聊天只发送一条简短送审消息，含任务、版本、文档链接和回复说明。修订后的通知增加简短修改摘要，不在消息中重复发送全文。

用户点击链接一次阅读完整方案，再回复对应送审消息。严格保持现有规则：去除首尾空白后只有“通过”批准当前版本；其他非空回复交 Solver 修订、机械校验后再送人工审查；空回复继续等待。人工反馈后的修订不调用 Critic。

飞书文档是现有 plan_review.markdown 的阅读呈现。不得通过 LLM 再生成另一份方案，不得改写或省略三个分组正文。门下省继续接收批准版本的原始正文，而非重新生成或实时抓取可能变化的文档。

## 备选方式

1. 完整飞书文档链接：推荐，适合手机阅读和较长方案，需要接入文档创建和阅读权限。
2. 完整文件附件：无需长文本分段，但阅读需要打开文件，体验取决于客户端。
3. 只发摘要：改动小，但缺少完整审查入口，不能满足人工批准完整方案的要求。

## 版本与批准关系

每个任务、版本发布一份文档，标题明确任务编号和 vN。旧版本作为历史记录，新的送审消息指向新版本。版本、原始正文哈希、文档标识和发送回执持久化；批准只能对应当前送审版本。旧消息中的“通过”不得批准新版。

文档尽可能以审阅者只读方式提供，修改要求继续通过回复送审消息提交。本次不接入文档评论或人工直接编辑作为反馈来源，避免出现未经 Solver 折回权威正文的变化。

## 发布与失败处理

先完成权威正文持久化和文档发布，再发送链接通知；确认通知投递成功后才记录已送达。发布和通知重试必须复用已知版本文档，不因普通发送失败再创建一份文档。对于创建结果未知的情况，需要先恢复创建结果，不能盲目重复创建。

文档发布失败或阅读权限未就绪时保留人工闸门，报告明确失败原因，不能自动放行到门下省，不能静默恢复分段全文发送。

实际文档接口与权限行为需在实现前通过官方 lark-cli 文档命令确认；目前仓库生产发送器只有文本消息能力，尚无文档发布实现。

## 验收

- 超过当前分段阈值的方案只有一条送审通知，文档包含全部三个分组。
- 文档正文来源与 plan_review.markdown 相同；门下省收到批准版本原始正文。
- 重复通知尝试不会额外创建同版本文档。
- 修改意见仅触发 Solver，新版送审之后旧版批准无效。
- 发布失败不记录送达、不放行；重启后保留版本和回复关联。
- 使用 python cmd/run_tests.py 的隔离适配器验证，不触碰当前运行任务、不通过测试发送真实飞书通知。

## 范围

调整中书省 PLAN_REVIEW 的文档发布和通知入口，不修改三个 Multica agent 的角色职责、普通初审过程或其他人工闸门。当前运行任务是否补发链接单独决定，不能通过重启来隐式迁移或重复发送。

批准范围内的实现继续在本会话完成。当前运行任务不自动重启或补发消息。
