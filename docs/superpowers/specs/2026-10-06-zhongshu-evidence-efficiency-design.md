# 中书省证据与失败恢复优化

用户已批准开始优化并要求品质、Multica skill 和协议一致。本批实现已确认的机制问题：补证覆盖旧证据、Analyst 汇聚校验失败丢弃成功结果、Critic 分组失败丢弃可用批准、回复重试重复调查。

保留同一需求契约下的历史证据，按证据 ID 与作用域合并，保留冲突观测与来源。需求契约变化必须新建证据包，历史证据不能自动证明当前代码正确。每轮新增证据预算和提示词切片预算维持不变；历史存储与单轮预算分离。

Analyst 每个成功结果先独立通过现有汇聚校验；失败时保存有效同伴、按 worker 反馈错误，重试只调度缺失结果。需求 ID 错误必须修复，不能自动替换伪造的 ID。Critic 失败波次仅保留完整有效的分组结果；已有批准仍受表面哈希、文档哈希及冻结检查保护。

回复修复携带有界的失败草稿，要求修格式而非重新调查。正常交付仍为唯一完整 inline JSON，结果文件仅用于已定义的平台超限兜底，保持中书省、门下省、agent 指令一致。

不改变人工精确“通过”门槛、人工意见由 Solver 修订再送审、唯一需求文档、引用校验、P0/P1 阻断。运行中的 prompt bundle 固定；静态 skill 发布对下一次 dispatch 生效。不会重启 8766 或改写活跃测试状态。

验收：针对覆盖、契约错误及分组部分失败的回归测试；脚本适配器流程检查；全量安全测试；Multica 三 agent 与相关 skill 回读一致且运行配置不变。时间收益仍需真实模型轮次测量。
