# 中书省可靠性加固设计

用户已要求在现有流程基础上仔细检查并完成稳定性、可靠性与效率加固。沿用已批准的方案审核、人审和补证设计，不引入审批放宽。

## 方案选择

选用现有闭合状态机的针对性加固。相比仅调大重试预算，这能消除重复工作而不延迟真实故障发现；相比另建调度框架，能保留已测试的持久化、hash 审批、freeze 与人审规则。

## 必须成立的不变量

1. 只有当前派发范围内的 Critic 可以关闭已有 finding。已关闭 finding 不再派发，不因其他组静默而关闭；明确重开须带真实新证据。P0 不允许静默消失。重复事件幂等，重启恢复保留关闭状态。
2. 补证返回只覆盖指定任务/需求。共享事实可以复用，但必须保留源证据 ID、原出处及原引用，明确当前任务关联，不能把相邻任务的验收结果冒充本任务通过。
3. 引用校验保留真实性标准。超长但已验证为真实连续原文的引用可以本地拆成有完整关联的短引用；失真、缺失与不可安全拆分仍进入有限 worker 修复。
4. 重试接收完整且有界的拒绝原因和原回复。预算不增加，失败的 worker 不拖累已成功 peer，不复用已结束的派发 identity。
5. 纯证据直达 Critic，文档与证据混合问题先补证再 Solver，正式任务图不被空包覆盖。
6. freeze、hash、版本、跨组依赖及唯一人工文档不变量保持；只有用户精确回复“通过”才能进入门下省，人工反馈仍仅 Solver 修订。

## 实现边界

新纯策略模块处理 Critic finding 关闭与复用校验，避免继续向大型 states.py 堆叠语义。传输适配器处理引用格式正规化与有界草稿交付；状态 reducer 仍是唯一持久化入口。

基于 task-20261006-c84b33 的第 6 轮 Critic → 第 7 轮 Analyst 归档做只读回放。运行中的任务不改写、不强制通过、不以重跑模型代替测试。现有 transport、lease、结果关联、重启与审批测试作为故障注入审计依据；没有实证缺陷的机制不另造实现。

## 验收

脚本驱动真实 OrchestratorApp 验证收敛；用当前派发归档验证只剩真实新缺口。覆盖部分成功、重复/过期事件、错误 scope、矛盾关闭、P0 静默、真实引文拆分、失真引文拒绝、完整修复草稿、跨阶段隔离和审批保护。全量走 cmd/run_tests.py 禁用真实通知；同步三 agent 与六 skill 并回读。没有实测之前不承诺固定 25–35 分钟或零外部故障。
