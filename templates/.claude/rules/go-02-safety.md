# 安全操作规则

## Git 操作

- **强制约束：禁止自动执行 Git 写入、历史改写或远端操作。** 只允许无副作用的 `git status`、`git diff`、`git log`、`git show`。执行 `git add`、`commit`、`push`、`pull`、`fetch`、`merge`、`rebase`、`reset`、`restore`、`checkout` / `switch`、`stash`、创建或删除 tag / branch，以及任何 force 参数前，必须取得用户对该具体操作的明确授权；一次授权不自动覆盖后续暂存、提交或推送。
- 不 force push（`--force` / `-f`）
- 不 reset --hard 他人分支
- 不删除远程分支（除非用户明确要求）
- 不 amend 已 push 的 commit
- commit 前必须 `go build` 通过

## 文件操作

- 不删除不认识的文件（先问用户）
- 不覆盖有未提交修改的文件
- 不修改 `gen_*_optiongen.go`（生成文件）
- 不修改 `wire_gen.go`（除非重新 wire generate）
- 不修改 `.env` / 配置中的密钥

## 验证规则

- 修改代码后必须 `go build -tags actor_id_uint64 ./cmd/server/` 通过
- 不能声称“已修复”但未验证编译或复现路径
- 不能声称“测试通过”但未运行测试
- 大范围修改后加跑 `go vet`

## 完成前证据规则

任何“完成 / 修复 / 通过 / 可合并 / 无问题”的结论，都必须先有本轮新鲜验证证据。

执行顺序：

1. 明确哪个命令或检查能证明该结论
2. 运行完整命令或完成对应检查
3. 阅读完整输出、退出码、失败数量
4. 只汇报证据支持的结论
5. 无法验证时明确说明原因和未验证风险

禁止用“应该可以”“看起来没问题”“理论上已修复”代替验证结果。

## 不可逆操作

以下操作执行前必须确认：

- 删除文件/目录
- 清空数据结构
- 修改数据库
- 重置配置
- 发送消息/邮件（游戏内）
