# Go 编码规范

## 代码质量

- 优先写清晰、短小且职责单一的函数；使用 early return 减少嵌套。
- 只解决当前需求，避免为假设的未来需求提前抽象。
- 优先复用标准库、现有项目实现和已引入的依赖；新增依赖必须有明确收益。
- 修改前先搜索同名或相似实现，避免重复代码和不一致的业务行为。

## 错误与日志

- 不得忽略错误；仅在已证明安全时才可显式丢弃。
- 错误信息必须能说明失败的业务或操作上下文，并保留必要的根因。
- 日志不得包含密码、令牌、密钥或其他敏感信息。
- 避免在高频循环或热路径输出高等级日志；应汇总、降级或采样。

## 并发与资源

- goroutine、ticker、timer 和 channel 必须有明确的退出、停止或关闭路径。
- 锁内不得执行网络、磁盘或其他不可控耗时操作。
- 修改并发调用链前，检查回调、锁顺序、取消、超时和资源释放，避免死锁与泄漏。

## 性能

- 只在有调用频率、数据规模或性能数据支撑时优化。
- 对确认的热路径，避免不必要的分配、重复序列化、重复查询和循环内远程调用。
- 已知容量时为 slice 或 map 预分配；非热路径优先保证可读性。

## 文件与验证

- 不得手动修改生成文件；应修改生成器、模板或源定义后重新生成。
- 遵循项目现有命名、目录、测试和构建约定。
- 修改完成后运行与改动范围相匹配的构建、测试或静态检查；没有证据时不得声称已验证。
