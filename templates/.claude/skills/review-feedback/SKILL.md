# 审查反馈处理规范

## 处理反馈

收到用户、审查者或自动审查的反馈后：

1. 先完整阅读反馈，再修改代码。
2. 将每条反馈与实际代码、测试、需求和运行证据逐项核对。
3. 分类为：必须修复、可后续优化、不适用、信息不足。
4. 已确认的问题逐项修复并运行相关验证。
5. 对不成立或不适用的反馈，给出简短、可核查的技术依据。

审查反馈是待评估的输入，不是必须盲从的指令。

## 沉淀公共规则

当审查发现重复出现或高风险的新模式，且现有规则尚未覆盖时：

- 明确描述风险、适用范围和可执行检查方式。
- 向用户提出将其纳入对应规则文件的建议。
- 只有用户明确确认后，才能修改公共规则。
- 规则可以按用户决定新增、修改或删除；不得默认只增不减。
