# Unity 逻辑修改规范

在 Unity 非 UI 或共享逻辑修改中按需读取；不得据此隐式启动或选择工作流。

## 执行要求

- 修改前定位调用方、当前行为和目标行为。
- 以最小必要范围为目标，不以最少代码行为目标；优先选择能完整解决问题且不会制造临时逻辑、重复代码或新的边界风险的方案。
- 如需扩大范围，只扩展到直接相关的调用链或抽象层，并说明原因、影响和验证方式。
- 保持兼容性；除非需求明确，避免 UI、Prefab、Scene 和生成文件变更。
- 检查空值、生命周期、异步、取消、超时和已销毁对象边界。

## 验证要求

- 验证旧行为未被意外破坏，以及新行为满足目标。
