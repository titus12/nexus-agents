# Cross-Config Skill

> 仓库: btd-config | 路径: D:/workspace/src/btd-config
> 职责: 协议定义(proto)、配置表(rawdata)、数据库状态(dbstate)、代码生成(xbean/xdb)
>
> §1 仓库结构 §2 核心目录 §3 开发流程 §4 关键规则 §5 调试指引 §6 常见问题

## §1 仓库结构

```
btd-config/
├── protos/              — protobuf 源文件
│   ├── msg/             — 客户端↔服务端消息 (.proto)
│   ├── actor/           — actor 间 RPC 消息
│   ├── inner/           — 内部消息
│   ├── dbstate/         — 数据库状态定义
│   ├── rawdata/         — 配置表数据结构
│   ├── rawdata_client/  — 客户端配置
│   ├── service/         — 服务接口定义
│   └── gameplay/        — 游戏玩法消息
├── gen/golang/          — Go 生成代码（不要手动改）
│   ├── msg/             — 消息 .pb.go
│   ├── actor/           — actor 消息
│   ├── conf/            — 配置访问器 (xxxconfig)
│   ├── rawdata/         — 配置表结构体
│   ├── dbstate/         — DB 状态
│   ├── xdb/             — xbean 数据层
│   └── service/         — 服务接口
├── excel               — 指向 Excel 配置表的链接
├── setting.yaml         — 生成工具配置
└── meta.json            — 元数据
```

## §2 核心目录用途

| 目录 | game-server 中的使用 | 说明 |
|------|---------------------|------|
| gen/golang/msg/ | Handler 的 req/resp 类型 | protobuf 消息 |
| gen/golang/actor/ | 跨 actor RPC 消息 | actor 间通信 |
| gen/golang/conf/ | xxxconfig.GetByKeyWithContext | 配置访问器 |
| gen/golang/rawdata/ | 配置表结构体 | Excel 导出 |
| gen/golang/xdb/xbean/ | entity.GetXxx() 返回类型 | 数据层接口 |
| gen/golang/dbstate/ | 数据库持久化状态 | DB schema |

## §3 开发流程（涉及 proto/配置变更时）

```
1. (Claude) 修改 btd-config/protos/ 中的 .proto 源文件
2. (用户) 运行代码生成（生成 gen/golang/ 下的代码）—— Claude 不执行、不查找生成工具
3. game-server 通过 go.work 自动引用本地 btd-config
4. (Claude) game-server 中使用新的消息/配置类型
5. 提交时两个仓库都要提交
```

⚠️ **代码生成分工（铁律）**：Claude 只改 `.proto` 源文件（dbstate/msg/service 等手写 proto），生成 `gen/golang/*.pb.go` 由**用户用 protokitgo 执行**。
- 改完 proto 后 Claude **停下等待用户生成**，不要去 PATH/磁盘搜索 `protokitgo`、不要尝试自己跑生成。
- 生成依赖新类型的 game-server 代码（如 `xbean.Xxx`、`msg.XxxReq`）必须等用户生成完毕再写，否则无法编译。
- 哪些是手写源 proto：文件头**没有** `Code generated by ProtoKit. DO NOT EDIT`；rawdata/*.proto 是 Excel 导出（有该头，不可手改）。

⚠️ Docker 构建用 go.mod 版本，本地改的 btd-config 需要先 push 才能影响 Docker 构建。

## §4 关键规则

- gen/ 下所有文件是**自动生成的，不要手动修改**
- 新增消息必须在对应的 .proto 文件中定义
- 新增配置表需在 setting.yaml 中注册
- xbean 字段变更影响数据库 schema，需谨慎
- rawdata 结构变更需同步更新 Excel 模板

## §5 调试指引

| 问题 | 查哪里 |
|------|--------|
| 消息字段不对 | protos/msg/对应.proto → 确认字段序号和类型 |
| 配置读不到 | protos/rawdata/ 确认结构 + gen/golang/conf/ 确认访问器 |
| xbean 字段缺失 | protos/dbstate/ 确认 DB 状态定义 |
| 编译报类型错误 | 可能 btd-config 本地未更新，`cd ../btd-config && git pull` |

## §6 常见问题

1. **本地编译报错**: btd-config 未更新 → `cd ../btd-config && git pull`
2. **proto 字段序号冲突**: 多人同时加字段 → 合并时检查 field number
3. **配置表零值**: rawdata 中字段未在 Excel 填值 → 返回 Go 零值
4. **go.work vs go.mod 版本不一致**: 本地能跑但 Docker 构建失败
